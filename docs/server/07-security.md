# 07 · 安全策略

> 原则：纵深防御。每一层（Nginx、Nest、ORM、MySQL、本地磁盘存储）各自承担明确责任，不依赖单点；所有安全控制默认开启，通过环境变量收紧而非放松。

## 1. 传输与网络安全

1. **全链路 HTTPS**：生产只开放 443，TLS 1.2/1.3，禁用 TLS 1.0/1.1 与弱密码套件；HTTP 301 跳 HTTPS。
2. Nginx 增加安全响应头：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: strict-origin-when-cross-origin`、`Content-Security-Policy`（H5 端按实际资源域名配置）。
3. CORS 白名单：只允许自家 H5 域名与小程序来源；`Access-Control-Allow-Headers` 仅放行 `Authorization/Content-Type/X-Request-Id/X-Client-*`；`credentials` 关闭（令牌不依赖 Cookie）。
4. 管理面（数据库 3306、Redis 6379）不对公网开放，仅本机/内网安全组可连；应用与数据层尽量同 VPC。
5. 在线更新服务（`static.shixian.xyz`）与业务 API 域名隔离，更新服务被攻击不波及记账数据。

## 2. 认证与会话安全

| 项            | 策略                                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------------------- |
| 密码存储      | **bcrypt，cost=12**；永不存明文、不落日志、不进错误信息                                                             |
| 密码规则      | 8~32 位；服务端不强求字符种类组合（避免用户写弱规律密码），但会拒绝「12345678」等常见弱口令 Top 列表                |
| 登录防枚举    | 账号不存在与密码错误统一返回「手机号或密码错误」；注册时手机号已注册才暴露存在性（可接受）                          |
| 登录防爆破    | 同手机号 5 次/15 分钟失败 → 锁定 15 分钟（40103）；同 IP 20 次/15 分钟；计数在 Redis                                |
| access token  | JWT/HS256，**2 小时**，载荷最小化（sub/jti/type/iat/exp），密钥 ≥32 字节且环境隔离                                  |
| refresh token | 30 天；库中只存 **SHA256 哈希**；刷新即轮换；旧令牌重用 → 作废该用户全部 refresh（泄漏检测）                        |
| 登出          | 吊销 refresh；客户端丢弃 access                                                                                     |
| 账号冻结      | 状态位在 JwtAuthGuard 中检查，冻结用户返回 40300                                                                    |
| 客户端存储    | access 放内存；refresh 使用 uni-app 的安全存储能力（App 端 plus 存储、小程序 storage 受沙箱保护）；不写入 URL/query |
| 密钥轮换      | 支持新旧 JWT 密钥并存一个发布周期；Redis 中可挂密钥版本号                                                           |

## 3. 数据加密方案

### 3.1 静态数据

| 数据          | 方案                                                                                                                                                                                                                                                              |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 用户密码      | bcrypt cost=12（单向哈希，不可逆）                                                                                                                                                                                                                                |
| refresh token | SHA256 哈希存库（原文仅签发时出现一次，存在客户端）                                                                                                                                                                                                               |
| 手机号        | v1 按明文存储（登录需要精确匹配，字段已建唯一索引）；列级访问最小化——除认证模块外，任何接口一律输出脱敏号 `138****8000`。若合规升级，演进方案：AES-256-GCM 加密存储 + 单独 HMAC-SHA256 盲索引列用于登录查询（密钥放 KMS），DDL 已预留改造空间（varchar 长度足够） |
| 头像/凭证图片 | 保存在服务端本地磁盘 `UPLOAD_DIR`（目录权限 `0700`、文件 `0600`），不放在任何 Web 静态根目录下；访问必须走 `/api/v1/files/` 签名 URL（HMAC，默认 12h），服务端实时签发，不存在永久直读链接                                                                        |
| 数据库备份    | 备份文件落独立备份盘/NAS 卷（与数据库、上传目录不同物理盘），文件系统权限限定为运维账号；可选整盘加密（LUKS/云盘加密）                                                                                                                                            |
| 密钥管理      | JWT 密钥、DB 密码、`FILES_SIGN_SECRET` 全部环境变量/部署平台密管注入，禁止入库、禁止打日志；生产与开发隔离                                                                                                                                                        |

### 3.2 传输中数据

- 外部：HTTPS/TLS（见 §1）；
- 应用 → MySQL/Redis：生产内网启用 TLS（云数据库默认强制）；
- 应用 → 图片文件：本地磁盘（或挂载的 NAS/NFS 卷）内网访问，不经过公网；对外只暴露 HTTPS 签名 URL。

### 3.3 金额与业务完整性

- 金额 `DECIMAL(12,2)` 精确类型，禁止用 FLOAT/DOUBLE；服务端 `round2` 与客户端同口径；
- 所有写操作以登录态 `userId` 为归属（取自 JWT，**绝不信任客户端传入的 userId**）；
- 危险操作（清空账单、删除账本）有 confirm 显式确认 + 限流 + 审计日志。

## 4. SQL 注入防护

1. **默认参数化**：全部数据访问经 TypeORM QueryBuilder/Repository，占位符绑定参数；从机制上消除拼接注入。
2. 禁止把 req 中的字符串直接拼入 `orderBy`、表名、列名：排序字段用**白名单映射**（前端只传 `date`/`amount` 等固定 key，映射到真实列名）。
3. 如确需原生 SQL（迁移/报表），同样使用参数绑定；code review 对 `.raw(`、`createQueryRunner.query(` 逐行检查。
4. LIKE 查询对 `%`、`_`、`\` 做转义（当前接口无模糊搜索，新增时遵守）。
5. MySQL 账号最小权限：应用账号只授予业务库的 `SELECT/INSERT/UPDATE/DELETE`，不给 `GRANT/FILE/DROP`；迁移单独使用高权限账号（仅发布时）。
6. 关闭多语句执行：连接串不开启 `multipleStatements`。
7. 错误响应不回显 SQL、表结构、堆栈（AllExceptionsFilter 对 5xx 只返回 50000 + traceId）。

## 5. XSS 攻击防范

本项目接口以 JSON 为主、页面由 uni-app 原生组件渲染（`<text>`/数据绑定默认不解析 HTML），XSS 面很小，但仍执行以下规范：

1. **输入校验**：DTO 白名单机制拒绝未声明字段；备注/昵称/账本名限长（50/12/12 字符），服务端 trim 后入库。
2. **输出编码**：客户端一律使用数据绑定渲染（`{{ remark }}`、`:value`），**禁止** `v-html`/`rich-text` 渲染服务端返回的用户文本；如未来引入富文本，必须经服务端白名单消毒（如 `sanitize-html`，仅保留安全标签）。
3. emoji 与多语言字符按普通文本处理（utf8mb4），不拼接到 HTML/URL 模板；拼 URL 时统一 `encodeURIComponent`。
4. H5 端 CSP 由 Nginx 下发：`default-src 'self'`；图片源限定 API 自家域名（`/api/v1/files/`）与 data:（默认头像）。
5. 图片上传只接受图像格式（见 §7），杜绝伪装成图片的 HTML/SVG 脚本：服务端 sharp 重编码压缩后再写入本地磁盘，去除原始文件中可能携带的脚本载荷；FilesController 输出时固定 `Content-Type: image/jpeg`、`X-Content-Type-Options: nosniff`，且 Nginx 关闭上传目录的自动索引（`autoindex off`）与任何脚本解析（`location ~* /api/v1/files/.*\.(php|jsp|sh|html?)$ { deny all; }`）。
6. 错误文案不回显用户原始输入（避免反射型 XSS 经由错误页），details 中的字段值供客户端以文本展示。

## 6. CSRF 防护机制

1. **鉴权不使用 Cookie**：令牌通过 `Authorization: Bearer` 请求头传递，浏览器跨站表单/图片标签无法自动携带该头——从根上免疫传统 CSRF，因此**无需 CSRF Token 中间件**。
2. 若后续运营后台改为 Cookie-Session 方案，必须同步启用：`SameSite=Lax/Strict` + 双重提交 Token（或 Nest 自带 CSRF 中间件），并在本文档补充。
3. CORS 不放通配符、不允许任意自定义头；预检请求由 Nginx/Nest 正常处理，非法来源在浏览器侧即被拦截。
4. 写接口只接受 `POST/PATCH/PUT/DELETE` + JSON（或带鉴权的 multipart）；`GET` 保证无副作用。

## 7. 文件上传安全

| 风险             | 措施                                                                                                                                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 可执行文件/木马  | 扩展名白名单（.jpg/.jpeg/.png/.webp）+ Content-Type 校验 + **魔术字节（file signature）校验**，三者一致才接收                                                                                       |
| 大小炸弹         | 单文件 ≤ 5MB；像素边长 ≤ 4096；Multer `limits` 在解析层先拦一次（内存占用上限）                                                                                                                     |
| 恶意内容         | 服务端重编码压缩（账单凭证长边 1440px/质量 0.82，头像 512px/0.85），丢弃原图元数据（EXIF 中的 GPS 等一并去除，附带隐私保护）                                                                        |
| 目录穿越/任意写  | 文件相对 key 由服务端生成（`bills/<userId>/<yyyy>/<mm>/<dd>/<有意义文件名>.jpg`），不接受客户端指定路径/文件名；落盘前 `path.resolve(UPLOAD_DIR, key)` 必须仍以 `UPLOAD_DIR` 为前缀，否则拒绝并告警 |
| 越权读文件       | 不开放目录直读；统一签名 URL（HMAC + 12h 过期，路径含 userId 不可猜测）；账单/头像 URL 只在登录鉴权后由服务端签发；签名失败与过期返回无差别的 403/404                                               |
| 盗用流量         | 上传接口 20 次/10 分钟限流；签名 URL 短时效不可枚举；孤儿文件 24h 清理；磁盘/inode 余量监控                                                                                                         |
| SVG 脚本         | 不接收 SVG（可内嵌 JS），位图 sharp 重编码为 JPEG 后落盘                                                                                                                                            |
| 磁盘耗尽         | 单文件 ≤ 5MB + 上传限流 + 每日清理任务兜底；共享卷设置磁盘配额（quota）；余量低于 10% 告警                                                                                                          |
| 多实例文件不一致 | 多实例必须挂载同一 NAS/NFS 共享卷或固定单实例，禁止各实例写各自本地目录（部署硬性要求，见 06 §4.2）                                                                                                 |

## 8. 敏感数据处理规范

1. **手机号**：任何响应默认脱敏 `138****8000`；仅账号本人在自己的资料接口可见脱敏号；日志正则脱敏。
2. **密码/token**：不得出现在 URL、日志、审计表、错误信息、埋点中；pino `redact` 配置路径 `req.headers.authorization`、`*.password`、`*.refreshToken`、`*.tokenHash`。
3. **个人财务数据**：账单、金额、账本均按用户隔离；越权访问统一返回 404（不区分「不存在」与「他人的」），防止资源探测；不提供任何「按手机号查别人账单」类接口。
4. **traceId 关联**：错误响应携带 traceId 用于排障；traceId 本身不含业务信息，可在客服场景收集。
5. **审计最小化**：`operation_logs` 只记方法/路径/状态/耗时/IP/UA/操作人，不记请求体与响应体。
6. **数据留存与删除**：账单删除后照片保留 7 天申诉期即物理清除；审计日志在线 3 个月；备份 6 个月后删除。v1 不提供账号注销接口，产品上线前如需合规，补充「注销 → 匿名化/级联删除」流程（外键已按 users RESTRICT 设计，需先迁移数据或改为按用户级联，发版前决策）。
7. **隐私最小收集**：不采集通讯录、位置、设备 IMEI 等；设备标识只用于 refresh token 管理，由客户端生成匿名 UUID，与在线更新系统的 deviceId 相互独立。
8. 接口返回遵循最小化：用户列表类能力不存在；资料接口只返回本人字段；字典/统计接口不泄露任何他人数据。

## 9. 依赖与运行时安全

1. `pnpm audit` 每周扫描，高危漏洞（远程可利用、有 PoC）当天升级；`npm ci`/锁版本保证可重复构建。
2. 容器以非 root 用户（`USER node`）运行；只读根文件系统（可选）、`--security-opt=no-new-privileges`。
3. 关闭生产 Swagger 文档与详细错误堆栈；开启 `app.enableShutdownHooks()` 优雅退出（等待在途请求结束，拒绝新连接）。
4. 限流分层：Nginx 全局限流兜底 + Throttler 业务级分档（登录/上传/写入各自独立阈值，见 03 §7）。
5. 定期检查 NestJS/Node 安全公告；Nest 全家桶统一升级大版本，避免单包漂移。
